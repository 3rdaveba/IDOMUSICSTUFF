Prima: new projects and existing projects

Prima is a local Python CLI for solo builders working with AI agents. You can introduce governance at the start or add it to a project already underway. Both paths are implemented in version 0.11.0.

Define the project before either command

Both commands require the project name, slug, owner, purpose, intended user, value proposition, initial scope, non-goals, proposed stack, and data classification. JSON configuration or CLI flags supply these requirements. For an existing project, describe its current reality; adoption does not reconstruct its history or audit the truth of those statements.

Validate after either path

prima validate ./project --html-report audit.html

Validation checks structural requirements, document references, owner authority wording, unresolved template tokens, and Git branch state. An adopted directory must already supply its README and CHANGELOG and be a Git repository on main for validation to pass. Adoption itself does not enforce those prerequisites or perform validation; run the validator afterward.

Repair and conflict boundaries

prima validate ./project --fix can recreate missing static instructions and three directory roles, after previewing each proposed write and asking for a response. It does not invent a charter or overwrite a living document. Supplied stdin can answer the prompt; it does not authenticate a human approver. Adoption refuses a conflicting governance path instead of merging it.

Current limits

A PASS is structural validation, not completed acceptance, a security certification, or proof that AI agents follow instructions. The repository records public launch as pending and the effectiveness study as design only. The CLI implementation is not changed for these demonstrations.
